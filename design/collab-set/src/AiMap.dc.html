Where a language model helps

The model turns facts into words and words into choices the engine can check. Analysis measures, the engine plays, the DJs decide.

Build first

1. Pairing explainer. Already in the brief; reference explanations exist as the baseline and offline fallback. 2. Where you stand. Text in, text out; cheap; directly serves the hardest collaborative moment. 3. Concept readings. The heart of the new direction, and the riskiest: it depends on observations the analysis cannot make yet.

What the analysis must add first

The model can only be as honest as its facts. Concepts need: Elements present per section: vocal, bass, melody, atmosphere. Needs a new spike, probably source separation or a small classifier. Key: imported from rekordbox, or typed by the DJ. No detection in the MVP. Groove similarity: the "same bass pattern" kind of observation; a research spike.

Where AI stays out

Choosing tracks or an order by default. An automatic set is available only when asked, and labelled as one reading. Settling a disagreement between the two DJs. Hearing audio: it receives features, never the music. Playing anything: control events come only from strategies and the DJs' own moves.
